# Спека: Social Board — дашборд и автоматизация соцсетей Вадима

Статус: **утверждена 19.10.2026.** План реализации этапа 1 — отдельный документ. Темп: Вадим выделяет 7–8 ч/день, этап 1 — 4 рабочих дня.

---

## 1. Зачем и для кого

**Цель.** Одно место, где видно, что работает, что публиковать дальше и кому ответить, — чтобы контентная система v2 выполнялась без ручного сбора скриншотов и чтобы Claude принимал решения по данным, а не по ощущениям.

**Пользователи.** Вадим (владелец, все права), Ксения/SMM (просмотр, черновики, публикация по согласованию), Claude через MCP (чтение данных, запись черновиков и разметки). Мультиаккаунтность с первого дня: RU и EN аккаунты, lifestyle-TikTok — всё в одной системе; архитектура допускает других пользователей (будущий SaaS), но в v1 — только одна «организация».

**Что НЕ делаем в v1.** Медиатека 100k файлов; автопостинг в LinkedIn (API закрыт — ручной ввод цифр); чтение чужих тредов Threads (API не даёт); автоматические ответы без подтверждения человеком; платёжные/SaaS-функции.

## 2. Пример-ориентир и отличия

Ориентир — Social Board Евгения Бисовки: Обзор с целями месяца и автокомментарием, Посты, Ответы, Сигналы, Черновики, Расписание, Люди/Аудитория, Челленджи, Источники. Наши отличия: (1) множитель к медиане и замер на 11-й день как базовая метрика вместо абсолютных просмотров; (2) RU/EN-конвейер адаптации внутри; (3) Telegram-статистика по каждому посту; (4) MCP-сервер для Claude; (5) фирменный стиль Вадима в UI — сезон «строю в паблике».

## 3. Архитектура

```
[Threads API] [Instagram API] [Telegram MTProto] [TikTok API*] [VK API*] [Virale/Chatplace] [ручной ввод LinkedIn]
        │             │               │                 │           │            │
   pg_cron→HTTP   pg_cron→HTTP    Railway worker     этап 3      этап 3     этап 2
   (Next.js       (Next.js       (Python,
    route          route          Telethon)
    handlers)      handlers)         │
        └─────────────┴───────────────┴──────────────► Supabase Postgres (vadim-social)
                                                              │
                      ┌───────────────────────────────────────┼────────────────────────┐
                      ▼                                       ▼                        ▼
             Next.js UI (Vercel)                      Claude API (Anthropic)      MCP-сервер (Vercel route)
             Обзор · Посты · Ответы · Черновики ·     черновики, автокомментарии,  read + write для Claude Code
             Расписание · Сигналы · Аудитория         подсказки ответов, EN-адаптация
                      │
             Telegram-бот (отчёты, сигналы) ← Railway worker
```
\* TikTok/VK — этап 3, после одобрения API-доступа.

**Стек.** Next.js 15 (App Router, TypeScript) на Vercel; Supabase (Postgres, Auth с magic link, Storage, Vault для секретов, pg_cron для расписаний); Prisma или Drizzle для схемы; Recharts для графиков; Tailwind + фирменная тема; Python 3.12 + Telethon + supabase-py для воркера на Railway; Anthropic SDK; MCP через `@modelcontextprotocol/sdk` с OAuth-ключом.

**Почему так.** Vercel и Supabase уже есть у Вадима; расписание — Supabase pg_cron + pg_net, который дёргает защищённые роуты Next.js каждые 6 часов (cron Vercel на бесплатном плане ограничен одним запуском в день); MTProto требует постоянного процесса — отдельный воркер; Postgres — одна база для всего, без очередей и Redis в v1.

## 4. Модель данных (ядро)

- `accounts` — платформа, хендл, язык (ru/en), роль (focus/mirror/lifestyle), токен (зашифрован), срок токена, статус синка.
- `posts` — account_id, внешний id, тип (reel, carousel, image, thread, tg_post, short, tiktok), дата публикации, текст/подпись, медиа-URL, pillar_id (связь с исходником), рубрика (столп), серия, язык, метка («залетело/мимо/странно»), ссылка на черновик.
- `post_metrics_snapshots` — post_id, снято_в, просмотры, охват, лайки, комментарии, сохранения, репосты, шеры, клики, среднее время просмотра; снимки на день 1, 3, 7, 11, 30 (и далее раз в неделю).
- `account_metrics_daily` — account_id, дата, подписчики, просмотры профиля, охват, новые подписчики (для накопленного прироста как у Жени).
- `benchmarks` — account_id, формат, период (75–90 дней), медиана просмотров/комментариев/сохранений, дата расчёта; множитель поста = метрика на 11-й день / медиана формата.
- `goals` — account_id, месяц, метрика (подписчики), цель, автокомментарий (текст + время генерации).
- `replies` — post_id, внешний id комментария, автор, текст, дата, статус (new / drafted / answered / ignored), черновик ответа, кто ответил, время ответа.
- `drafts` — тип (reel_script, thread, tg_post, carousel, linkedin, story), язык, статус (idea / draft / approved / scheduled / published), текст, хуки (массив), pillar_id, рубрика, CTA, назначенная площадка, дата публикации.
- `pillars` — исходный материал недели (TG-пост / съёмка), ссылка, дата, список порождённых drafts.
- `signals` — тип (×3 за 24 ч, тема из комментариев, просадка недели, 11-й день, токен истекает), payload, статус, создан_в.
- `bricks` — «кирпичи»: наблюдение, источник (post_id/период), статус (гипотеза / подтверждено), добавлен.
- `audience_profiles` (этап 4) — автор взаимодействия, платформа, классификация Claude (предприниматель/маркетолог/инвестор/прочее), уверенность.
- `manual_metrics` — для LinkedIn и любых площадок без API: дата, подписчики, просмотры.

Инварианты: один внешний id = одна запись `posts` (уникальность account_id + external_id); снимки метрик не перезаписываются, только добавляются; токены — только в зашифрованном виде; удаления «мягкие» только для drafts.

## 5. Модули и этапы

### Этап 1 (недели 1–2): данные и Обзор
- Сборщики: Threads (посты, инсайты постов и пользователя, подписчики), Instagram (медиа, инсайты Reels/постов, подписчики), Telegram (подписчики, просмотры/репосты каждого поста, источники, рост) — каждые 6 часов; снимки на 1/3/7/11/30 день.
- Обзор: карточки по площадкам (подписчики, прирост вчера/сегодня, цель месяца с прогрессом, автокомментарий в голосе Вадима — Claude раз в день), график накопленного прироста за 30/90 дней, просмотры и реакции за период.
- Посты: единая таблица, фильтры по площадке/формату/рубрике/языку, множитель, метка, сортировка; карточка поста с историей снимков.
- Бенчмарки: автоматический пересчёт медиан 1-го числа месяца и по кнопке.
- Вход: Supabase Auth, magic link, allowlist из двух e-mail (без отдельного пароля — одна система входа); тёмная тема в фирменном стиле.

### Этап 2 (недели 3–4): Ответы, Черновики, MCP
- Ответы: входящие комментарии Threads и Instagram в одной очереди; Claude генерирует черновик ответа по «Голосу Вадима» и истории поста; публикация одним нажатием (Threads reply API / Instagram comment reply); учёт «ответил лично / команда».
- Черновики: pillar → «размели» (Claude: 4 сценария Reels, 5 Threads, карусель, 2 сторис) → редактирование → статус; EN-адаптация кнопкой (перевод + новый хук + замена примеров); банк хуков; чек-лист перед публикацией из «Сторителлинга».
- Virale/Chatplace как источник аналитики Instagram и конкурентов (через существующий MCP — импорт срезов раз в неделю).
- MCP-сервер: инструменты `get_overview`, `list_posts`, `get_post`, `top_posts`, `list_replies`, `create_draft`, `update_label`, `add_brick`; OAuth-ключ для Claude Code и claude.ai.
- Ручной ввод LinkedIn.

### Этап 3 (недели 5–6): публикация, сигналы, отчёты
- Расписание: календарь недели с ролями площадок; публикация в Threads и Instagram из дашборда (медиа в Supabase Storage → публичный URL → API); Telegram через бота; TikTok/VK — через их API после одобрения (иначе — напоминание «опубликовать руками» с готовым файлом и текстом).
- Сигналы: пост ×3 к медиане за 24 ч; повторяющийся вопрос в комментариях (Claude-кластеризация); просадка недели; 11-й день; токен истекает через 7 дней; цель месяца отстаёт от темпа.
- Отчёт недели в Telegram-бот (пятница 10:00): цифры, топ-3 поста с множителями, что повторить, очередь ответов, сигналы.
- Разбор топ-10% месяца: Claude ищет 1–2 общих элемента, предлагает «кирпичи» на подтверждение.

### Этап 4 (после 6 недель): аудитория и расширения
- Аудитория: демография Threads/IG, источники подписчиков TG, классификация взаимодействующих (предприниматель/маркетолог/инвестор).
- Челленджи (как у Жени): личные цели по постингу и ответам с прогрессом.
- Хакатон-режим: отдельный раздел для экспериментальных постов с отдельным бенчмарком.
- Медиатека (разметка футажа) — отдельная спека.
- Мультипользовательский режим и SaaS — отдельная спека, если решение принято.

## 7. Claude внутри дашборда — правила

- Все генерации — по документу «Голос Вадима» (системный промпт собирается из файлов проекта и хранится в базе, версия помечается).
- Ничего не публикуется без явного действия человека. Автокомментарии к метрикам — исключение (они внутренние).
- Факты и цифры — только из `posts`/`benchmarks` и утверждённого списка фактов; черновик с незаполненным фактом помечает пропуск `[?]`.
- Каждая генерация пишет в лог: промпт-версия, модель, стоимость, принят/отклонён — чтобы учиться на принятых.

## 8. Безопасность

- Токены площадок и сессия Telegram — только зашифрованные (AES-GCM, ключ в переменных окружения), в UI не отображаются.
- `service_role` ключ — только на сервере; браузер работает через RLS с ролью пользователя.
- Вход: magic link с allowlist e-mail; две учётки (Вадим — owner, SMM — editor).
- Публикация и ответы — подтверждение в UI; лог всех исходящих действий.
- Резервное копирование Supabase (ежедневно, встроенное).

## 9. Ошибки и наблюдаемость

- Каждый сборщик пишет `sync_runs` (аккаунт, начало/конец, статус, число записей, ошибка). Три неудачных синка подряд → сигнал в бот.
- Rate limits Meta — экспоненциальная пауза и повтор; частичные результаты сохраняются.
- Истечение токена — сигнал за 7 дней + ссылка на повторную авторизацию.
- Health-страница `/api/health` с датой последнего успешного синка по аккаунтам.

## 10. Тестирование и приёмка

- Этап 1 принят, когда: все три RU-аккаунта синкаются 48 часов без ручного вмешательства; Обзор показывает цифры, совпадающие с нативной статистикой (±5% с учётом задержек Meta); множители считаются для всех постов старше 11 дней.
- Этап 2: 20 ответов опубликованы из дашборда; один pillar «размолот» в пакет и 4 Reels из него вышли; MCP отвечает из Claude Code.
- Этап 3: неделя постинга полностью из дашборда (Threads, Instagram, Telegram); пятничный отчёт пришёл сам.

## 11. Риски

- Meta меняет API/права — изоляция сборщиков по адаптерам, один адаптер = один файл.
- Порог статистики Telegram — если `can_view_stats` нет, собираем просмотры постов через обычный `GetHistory` (views есть у сообщений канала) и подписчиков через `GetFullChannel`; графики источников будут позже.
- Объём времени Вадима — дашборд снижает ручную работу, но не заменяет съёмку и ответы; это закреплено в контентной спеке.
- Соблазн «сделать всё сразу» — этапы с приёмкой; новая функция только после приёмки предыдущего этапа.
